# Work bridge MVP [P(3-1)]

**건물 유지보수 외주 매칭 플랫폼** — 건물주(의뢰인)와 유지보수 전문가(프리랜서)를 연결한다.

> 가격을 먼저 합의하지 않습니다. **범위**를 먼저 합의합니다.

---

## 문제

건물 보수 외주에서 분쟁의 원인은 가격이 아니라 **범위**다.

> 견적 300만원이라고 해서 맡겼는데, 뜯어보니 이것도 해야 한다며 끝나고 500만원을 요구한다.

건물주는 얼마가 적정한지 모르고, 전문가는 어디까지가 약속한 일인지 문서가 없다.

## 해법 — 한 번 쪼개고 끝까지 쓴다

AI가 프로젝트 설명을 **단위 공정으로 분해**하고, 그 결과를 네 곳에서 재사용한다.

```
프로젝트 설명 ("3층 화장실 천장 누수, 아래층까지 번짐")
        │
        └─ AI 공정 분해 (1회)
             ├ 누수 원인 진단   18만   ├ 배관 교체      95만
             ├ 방수 재시공     140만   └ 타일·마감 복구  67만
                      │
      ┌───────────────┼────────────────┬──────────────────┐
      ▼               ▼                ▼                  ▼
  ① 예상 단가     ② 계약서의       ③ 작업 마일스톤    ④ 부분 정산 단위
     합계 320만      공사 범위 조항     (기성 단계)       단계 승인 시 지급
```

분해 결과를 리포트 화면에서 버리지 않는 것이 이 제품의 전부다.

## 기술 스택

| 영역 | 선택 |
|---|---|
| 프레임워크 | Next.js (App Router) · TypeScript |
| DB · ORM | PostgreSQL · Prisma |
| 인증 | 자체 JWT (Access / Refresh) + OAuth 2.0 |
| 결제 | PG sandbox |
| AI | LLM API (구조화 JSON 응답) |
| 배포 | Vercel (GitHub 연동 자동 배포) |

## 진행 방식

1인 진행이므로 협업 산출물은 1인 다역 운영 기록으로 대체한다.

- `main` ← `feat/*`, 직접 push 금지 · PR 경유
- PR 본문에 구현 의도와 판단 근거를 기록
- 작성자 / 리뷰어 시점을 분리한 셀프 코드 리뷰
- 2 스프린트 · 칸반 보드 · 스프린트별 계획서와 회고록

## 개발

```bash
npm install
cp .env.example .env    # 값 채우기
npx prisma migrate dev
npm run dev
```

> 결제는 **sandbox 전용**이다. 실제 결제가 발생하는 키를 넣지 않는다.
