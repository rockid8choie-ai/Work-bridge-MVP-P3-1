### 판단한 것

**인증을 직접 구현했다.** Supabase 같은 기성 서비스를 쓰면 명세 3.1.1("Access Token 발급 + 만료 시 Refresh로 자동 재발급")의 학습 목표를 건너뛴 것이 된다. 구현하면서 네 가지를 정했다.

- Refresh 는 JWT 가 아니라 난수다. 의미를 담지 않으니 서명할 이유가 없다.
- Refresh 는 DB에 SHA-256 해시로만 저장한다. 평문을 두면 DB 유출이 곧 세션 탈취다.
- 재발급할 때 쓴 Refresh 를 즉시 폐기한다(rotation). 유출돼도 한 번만 쓰인다.
- 로그인 실패 시 "계정 없음"과 "비밀번호 틀림"을 구분하지 않는다. 이메일 존재 여부를 알려주면 안 된다.

**`ScopeItem` 을 JSON 이 아니라 행으로 뒀다.** 이 프로젝트의 차별화 축은 "AI 분해 결과를 끝까지 재사용하는 것"인데, JSON 한 칸에 담으면 리포트 화면을 벗어나는 순간 쓸 수 없다. 행으로 쪼개야 `Milestone` 이 `scopeItemId` 로 참조해서 **공정 하나 = 계약 범위 조항 = 마일스톤 = 정산 단위**가 성립한다. 차별화가 DB 구조에 박혀 있어야 나중에 흔들리지 않는다.

**프로젝트 상태를 두 축으로 나눴다.** 외부 목록에는 모집 단계만 노출해야 하는데(B-17) 단일 enum 이면 조회마다 변환이 붙는다. `recruitStatus` / `dealStatus` 로 나누니 외부 질의는 전자만 보면 된다.

**프로필 차단을 전용 상태 코드로 분리했다.** 일반 400 으로 내리면 클라이언트가 "입력 오류"와 "프로필 없음"을 구분하지 못한다. 428 `PROFILE_REQUIRED` 로 따로 두니 화면이 그 코드만 보고 `/profile?next=...` 로 보낼 수 있다.

### 막혔던 것

**Docker 로 로컬 DB 를 띄우려다 실패했다.** 엔진이 계속 500 을 반환했는데, 원인은 메모리였다. 전체 15.6GB 중 여유가 0.4GB 뿐이라 Docker Desktop 의 리눅스 VM 이 못 떴다. 어차피 배포에 클라우드 DB 가 필요하므로 Neon 으로 전환했고, 결과적으로 개발·배포 DB 가 한 번에 해결됐다. **로컬 환경을 고집하지 않은 것이 맞는 판단이었다.**

**빌드가 두 번 죽었다.** `JS heap out of memory`. Next 가 기본적으로 코어 수만큼(11개) 워커를 띄우는데 메모리가 모자랐다. `experimental.cpus: 2` 로 제한해 해결했다.

**CSS 파싱 실패.** `@import` 는 다른 규칙보다 먼저 와야 하는데 Pretendard 임포트를 `@import "tailwindcss"` 아래 뒀다. 순서를 바꿔 해결.

**테스트 오탐 하나.** 프로필 저장이 400 으로 떨어져 enum 검증 버그인 줄 알았는데, Git Bash 가 한글을 깨뜨려 보낸 것이었다. UTF-8 파일로 전송하니 정상. **도구가 만든 실패를 코드 버그로 오인할 뻔했다.**

### 판단한 것

**AI 는 맞히는 게 아니라 초안을 쓴다.** "공사는 변수가 너무 많지 않나"는 질문에 답하다가 정리됐다. 제품의 주장은 "AI 가 공사비를 정확히 산정한다"가 아니라 "무엇을 할지 항목으로 적고, 전문가가 고치고, 양쪽이 서명한 뒤 시작한다"다. 변수가 많을수록 사전에 적어둔 항목 목록의 가치가 올라간다. 그래서 AI 를 세 겹으로 가둔다 — 카테고리별 공정 사전에서만 고르기, 단가 범위 안에서만 쓰기, 구조화 JSON + zod 검증 + 규칙 폴백.

**계약서 범위 조항은 AI 원안이 아니라 전문가 수정안이다.** 개요 문서 초안에 "계약서 범위는 AI 공정표 그대로"라고 썼다가 설계와 어긋나는 걸 발견해 고쳤다. 흐름: AI 초안 → 수락된 전문가가 행 추가·삭제·수정 + 사유 → 건물주 동의 → 계약서 생성 → 서명 시 사본 고정. 고친 행은 원안과 구분 표시한다.

**"뜯어보니 다르다"에 자리를 만든다.** 공사 변수의 대부분은 진단 후 범위가 바뀌는 데서 온다. 현재 설계에는 계약 후 범위 변경 흐름이 없었다. `ScopeChange`(누가 요청했나 · 전/후 · 양측 동의 시각) 를 ERD 에 추가하기로 했다. 구현은 도전 과제. 소비자분쟁해결기준이 "사업자 요청 변경은 소비자 부담 없음, 소비자 요청 변경은 소비자 부담"으로 정하므로 **요청자 기록이 곧 방어 논리**다.

**프로젝트 등록에 0단계 자연어 입력을 붙인다.** 한 줄 설명 → AI 가 카테고리·전문분야·키워드 추출 → 3단계 폼 미리 채움. 3단계 폼은 RFP 기본 필수라 유지. 스프린트 1 끝나고 붙인다.
