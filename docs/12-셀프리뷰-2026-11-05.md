## 1. 외부 피드백 검증부터

받은 피드백: *"고급 필수 미구현. 배포 사이트에서 가입→지원→계약→결제→리뷰 중 '지원 수락' 까지만 동작."*

**사실과 다르다.** 배포본(workbridge-gray)에 `SKIP_PAYMENT=1 bash scripts/e2e-sprint2.sh` 를 돌려 **62/62 통과** — 가입 → AI 분해 → 예산 반영 → 지원 2명 → 수락 → 전문가 범위 수정 → 금액 제시 → 동의 → 계약서 자동 생성 → 양측 서명 → 체결 → 마일스톤 생성 → 결제 대기, 거부 경로, 화면 라우트까지. 결제 이후(에스크로 → 단계 승인 → 리뷰)는 토스 sandbox 결제창을 거쳐야 해서 배포본 스크립트는 건너뛰고, 로컬 시뮬레이션 모드에서 103 검사로 확인한다.

**그래도 리뷰어가 그렇게 본 이유는 우리 쪽에 있었다.**
1. `PROGRESS.md` 머리글이 10/26 상태 "고급 필수 미구현" 그대로였다. 리포를 먼저 읽는 사람은 그 문장을 믿는다. → PR #30 에서 갱신.
2. 지원자 관리 화면에서 **수락을 누르면 버튼만 사라지고 다음 단계로 가는 길이 없었다.** 거래 화면 링크는 내 공사·내 지원·공사 상세에만 있었다. 심사자는 수락을 누른 화면에서 멈춘다. → PR #30 에서 "거래 화면으로 →" 배너(다음 6단계 안내) 추가.

교훈: **기능이 있어도 진입점이 없으면 없는 것이다.** 상태가 바뀌는 모든 화면은 다음 행동을 같은 자리에 보여야 한다.

### 잘 돼 있는 것 (바꾸지 말 것)
- 결제 금액은 **서버 저장값으로만 승인**하고 쿼리스트링 amount 는 비교만 한다. live 키는 접두사로 차단.
- OAuth `state` 는 쿠키에 해시·URL 에 원문, 처음 보는 사용자의 프로필은 10분 서명 토큰 쿠키로만 넘긴다(쿼리스트링에 이메일 없음).
- AI 출력은 zod 통과분만 저장하고 합계는 서버가 다시 계산한다. ETC 비율 초과는 폴백.
- 리뷰는 DB 유니크(P2002)로 방향별 1회를 강제 — 애플리케이션 검사만 믿지 않는다.
- 상태 전이 + 알림은 전부 한 트랜잭션.
