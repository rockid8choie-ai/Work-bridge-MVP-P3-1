# 04. 산출물 리스트 및 제출 가이드

> 과제 가이드 원문. 2026-10-13 사용자 전달분.

## 1. 산출물 리스트

여러분이 수행한 프로젝트의 결과물을 효율적이고 체계적으로 제출할 수 있도록, 아래 가이드를 참고해 주세요. 모든 산출물은 일관된 형식과 명명 규칙을 따르고, 최종 점검을 완료한 후 제출해야 합니다.

### (1) 프로젝트 최종 발표 자료
- ✅ 프로젝트 개요, 주요 기능 시연, 개발 과정 및 회고를 포함한 최종 발표 자료
- 제출 형식: PPT or PDF

### (2) 개발 산출물
- ✅ **배포된 서비스** — 제출 형식: URL (Vercel 등)
- ✅ **소스 코드 리포지토리** — 제출 형식: URL (GitHub)
- ✅ **ERD**: 데이터베이스 설계 다이어그램 — 참고 도구: dbdiagram.io, draw.io 등 — 제출 형식: PNG 또는 PDF + 원본 링크
- ✅ **API 명세서**: 모든 엔드포인트 정의 문서 — 참고 도구: Swagger, Postman, Notion 등 — 제출 형식: PDF + 원본 링크

### (3) 프로젝트 관리 산출물
- ✅ **프로젝트 관리 워크스페이스**: 스프린트 계획서, 칸반 보드, 스프린트 회고록(2회 이상)을 하나의 워크스페이스로 통합 — 참고 도구: Notion, GitHub Projects 등 — 제출 형식: URL (모든 항목이 한 페이지나 워크스페이스 안에서 접근 가능해야 함)

## 2. 제출 가이드

제출은 (1) 기수별 결과물 공유 노션 DB와 (2) 코드잇 LMS 총 2군데에 진행합니다. 정확한 링크는 디스코드 공지를 참고해 주세요.

### 기수별 결과물 공유 노션 DB 제출
노션 DB 페이지에 아래 링크들을 반드시 포함하여 제출하며, 제출 전 각 링크가 외부에서 보기 가능한 형태로 설정되어 있는지 꼭 확인해 주세요.
- 배포된 서비스 URL
- GitHub 리포지토리 링크 (여러 개일 경우 모두 제출)
- 발표자료 원본 링크
- 개발 산출물 링크 (ERD, API 명세서)

### 코드잇 LMS 제출
다음 산출물은 지정된 파일 형식으로 Export한 뒤, LMS로 제출합니다.
- 발표자료: PPT or PDF 파일
- 팀 노션 링크: URL

## 3. 파일 명명 규칙

체계적인 관리를 위해 아래 규칙을 엄수해 주세요.

```
[팀명]_[산출물명]_[버전].[확장자]
예) TeamAlpha_FinalPresentation_v1.0.pdf
예) TeamAlpha_ERD_v1.0.png
```

## 4. 제출 기한

- 프로젝트 최종 발표일 전일까지 모든 산출물을 제출
- 발표 날, 발표 자료는 프로젝트 관리 워크스페이스 내 최종 버전으로 정리해서 제출

## 5. 파일 제출 전 점검 체크리스트

- [ ] 배포 URL이 정상적으로 동작하나요? (회원가입부터 결제, 리뷰까지 종단간 시연 가능)
- [ ] GitHub 리포지토리가 public 또는 강사/멘토 접근 가능 상태인가요?
- [ ] `.env` 파일이 커밋되지 않았고, `.env.example`이 함께 제공되나요?
- [ ] ERD와 API 명세서가 최신 코드와 일치하나요?
- [ ] 프로젝트 관리 워크스페이스 권한 설정이 '보기 가능' 또는 '편집 가능'으로 되어 있나요?
- [ ] PG 결제가 sandbox(테스트 환경)로 동작하나요? (실제 결제 발생 금지)
- [ ] 최종 발표 자료의 폰트가 깨지지 않는지(PDF 권장) 확인했나요?

> ⚠️ 모든 산출물은 수료 이후에도 공개 상태로 유지해 주세요.
