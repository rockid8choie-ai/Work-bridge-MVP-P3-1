# 05. 최종 발표 가이드

> 과제 가이드 원문. 2026-10-13 사용자 전달분.

## 1. 발표 자료 목차 예시

한 팀당 발표는 질의응답 시간을 포함하여 **20-25분 내외**로 진행됩니다. 아래 목차를 참고하여 프로젝트 발표자료를 구성해 보세요.

1. **표지 및 팀 소개**
   - 프로젝트명 및 팀명
   - 팀원 소개 (이름 및 역할)
2. **프로젝트 개요 및 배경**
   - RFP에서 정의된 도메인과 비즈니스 흐름 소개
   - 주요 사용자 및 타겟 (의뢰인 / 프리랜서)
3. **요구사항 이해 및 MVP 우선순위 결정**
   - RFP에서 정의된 문제 상황과 타겟 사용자에 대한 팀의 해석
   - 기본 필수, 고급 필수, 도전 과제 중 어디까지 어떤 우선순위로 진행했는지
   - 모호하거나 명세에 없던 부분에 대한 팀의 자율 결정과 그 근거
4. **데이터 모델 및 API 설계**
   - ERD 및 핵심 엔티티 설명
   - 주요 API 설계 의도 설명
5. **시스템 아키텍처 및 도구 선택**
   - 서비스 구성 및 모듈, 레이어 분리 방식
   - 팀이 선택한 라이브러리 및 도구와 선정 근거
   - 상태 관리, 배포 방식, 외부 API 클라이언트 등 (고정 기술 스택 내에서 자율 결정한 영역)
6. **주요 기능 시연**
   - 회원가입 → 프로젝트 등록 → 지원 → 알림 → 계약/결제 → 리뷰까지의 핵심 플로우 시연
   - AI 단가 분석, PG 결제 등 차별화 요소 강조
7. **개발 과정 및 기술적 난제**
   - 스프린트별 진행 상황 및 주요 의사결정
   - 마주한 기술적 난제와 해결 방법 (OAuth 흐름, OpenAI 응답 파싱, PG 콜백 검증 등)
8. **마무리 및 팀원 회고**
   - 팀원들의 주요 배움과 성장 포인트
   - 프로젝트를 통해 얻은 인사이트
9. **질의응답 안내**

## 2. 발표 자료 필수 포함 내용

### 요구사항 이해 및 MVP 우선순위 결정
- RFP에서 정의된 문제 상황과 타겟 사용자에 대한 팀의 해석
- 기본 필수, 고급 필수, 도전 과제 중 어디까지 어떤 우선순위로 진행했는지 설명
- 모호하거나 명세에 없던 부분에 대한 팀의 자율 결정과 그 근거

### 데이터 모델링 및 API 설계의 의도
- 핵심 엔티티 관계 설명
- 주요 API의 설계 의도

### 실제 동작하는 서비스 시연
- 배포 환경에서의 시나리오 기반 시연
- 회원가입 → 프로젝트 등록 → 지원 → 알림 → 계약 및 결제 → 리뷰까지의 핵심 플로우 시연
- PG 결제, AI 단가 분석 결과 등 차별화된 기능 시연

### 개발 과정에서의 의사결정 및 회고
- 아키텍처 결정의 트레이드오프 및 팀이 선택한 라이브러리·도구의 근거
- 스프린트 회고를 통해 도출된 인사이트

### 팀워크 및 역할 분배
- 팀원이 어떤 영역을 담당했는지 간략히 정리
- 협업 과정에서의 커뮤니케이션 방식과 협업 도구 활용 방법

> 1인 진행이므로 "팀워크 및 역할 분배"는 **1인 다역 운영 기록**(PR 경유, 셀프 리뷰, 칸반, 회고)으로 대체한다. [`../01-요구사항-분해.md`](../01-요구사항-분해.md) "1인 운영 방식" 참고.
